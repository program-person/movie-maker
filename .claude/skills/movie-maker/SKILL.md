# movie-maker：ずんだもん解説動画を作る

コード一式は公開リポジトリ https://github.com/program-person/movie-maker にある。
台本 JSON を書き、`build.py` で「読み上げ → シーンごとの描画 → 仕上げ」を行う。

## 役割分担（必ず守る）

- Claude：調べる、台本を書く、動画ファイルを作る。
- 人：事実確認と投稿。Claude は「確認済み」と扱わない。投稿もしない。

## 流れ

1. 環境ごとの手順を読む。
   - `/mnt/user-data` がある（claude.ai のチャット）→ `references/chat.md`
   - それ以外（Claude Code）→ `references/claude-code.md`
2. 題材を調べ、出典の URL を集める（下の「出典」）。
3. 台本 JSON を書き、`python3 build.py check 台本.json` を通す（スキーマ＋描画前チェック）。
4. **ここで止めて確認を待つ（既定）。** 台本と「確認してほしい事実の一覧」を出す。
   - 依頼文に「確認なしで」「動画まで一気に」などの明示があるときだけ、止めずに 5 へ進む。
     その場合も、同じ一覧を動画と一緒に出す。Claude の判断で止めるのを省かない。
5. 読み上げ（`voice`）→ 出てきたカナを読み、読み間違いがあれば speak を直して `voice` からやり直す。
6. シーンごとに描画（`scene`）→ 仕上げ（`finish`、最後に自動で verify が走る）。
7. 動画と台本を渡す。読みで気になった箇所と、確認してほしい事実の一覧を添える。

エラーが出たら、メッセージが指す場所を直して、その段からやり直す。
チェックを外したり、通すためにしきい値を変えたりしない。

## 確認してほしい事実の一覧（手順4・7で出す）

台本に出てくる数値・日付・固有名詞・「〜になった」といった主張を、シーン番号と出典つきで表にする。

| シーン | 主張 | 出典 |
|---|---|---|
| 02 | Terminal-Bench 4.0 で 66.4% | Anthropic 公式発表 |

出典が見つからなかった主張は台本に入れない。どうしても入れたいときは、一覧で「出典なし」と明記する。

## 出典

- `meta.sources` に1件以上（スキーマで必須）。URL は Web 検索で実際に開いたページのものだけを書く。記憶から作らない。
- 公式発表を優先し、報道・第三者の数値は「〜という指摘もある」のように出どころがわかる言い方にする。
- 記事の文章をそのまま字幕に写さない。言い換える。
- 「たった1つ」「必ず」「すべて」のような言い切りは、出典に並んでいる項目を全部見てから書く
  （例：規約の条件が複数あるのに「条件は1つ」と書かない）。
- `meta.credit` は画面下の短い表記（例：`出典：Anthropic公式発表（2026/9/22）`）。音声のクレジット（VOICEVOX:ずんだもん）は自動で入る。

## 台本の書き方

正確なキーと制約はリポジトリの `docs/handoff.md` の「4. 台本 JSON の仕様」、見本は `samples/opus55_full.json`。
スキーマに合わないキーはエラーになるので、推測で足さない。

### 長さと構成

- 全体 60〜150 秒が目安（見本は約 140 秒・9シーン）。1シーン 10〜25 秒、セリフ 2〜5 行。
- 最初は `hook`（つかみ）、最後は `end`（締め）。間に中身のシーンを 3〜7 個。
- 見出しの `num` は "01" から順に振る。

### セリフ（lines）

- `text`：字幕に出す文。ずんだもんの口調で、文末は「〜のだ」「〜なのだ」。1行 40 字くらいまで。
- `speak`：読み上げ用の文。text と同じ内容で、次のように直す。
  - 英語・略語はカタカナ（Claude → クロード、Opus → オーパス）。「AI」はそのままでよい。
  - 「%」は「パーセント」。
  - 間を置きたい所に読点「、」を足す（例：`約4割、安くなったのだ`）。
- `cue` は「lines の何番目のセリフで画面に出すか」（0 始まり）。セリフで触れる瞬間に合わせる。
  セリフの途中で出したいときは `delay`（秒）を足す。

### どの型を使うか

| 型 | 使いどころ |
|---|---|
| hook | つかみ。タイトル1〜2行・一言・大きい数字・問いかけ |
| tier | 位置づけ（上位・今回・前のもの を2〜3段で） |
| bars | 数値の比較（最大3系列×3行の棒グラフ） |
| price | 料金などの 旧 → 新 と、まとめの帯 |
| cards | 印象的な数字を大きく見せる事例（最大2枚） |
| list | 箇条書き（2〜3項目が見やすい。1項目だと下半分が空く）。注意点は `style: "warn"` |
| end | 締め。文字を自由に置く（`y` と `size` を指定） |

色は名前で指定する：`fg`（白）/ `sub`（薄い灰）/ `acc`（オレンジ）/ `warn`（黄）/ `gray` / `blue`。
主役（今回の題材）を `acc`、比較相手を `gray` や `blue` にする。

### 描画前チェックで止まったら

`check` のエラーは「どのシーンの、どの文字が、どこにはみ出したか」を示す。
文を短くする、`\n` で改行位置を決める、項目を分ける、のどれかで直す。
行頭禁則・speak の英字は警告なので、内容を見て直すか判断する。
